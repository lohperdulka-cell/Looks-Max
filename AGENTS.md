# AGENTS.md — заметки по репозиторию

## Что это
FaceMetric — веб-платформа оценки пропорций лица (ниша looks-max), студия VA digital studio.
Backend и ML на Python (FastAPI async + NumPy/OpenCV/MediaPipe/InsightFace).
Фронтенд — только Jinja2, HTML, CSS и vanilla JS. Никаких Node, bundler'ов,
TypeScript или React: это жёсткое требование заказчика.

## Команды
```bash
. .venv/bin/activate
ruff check app tests && ruff format app tests
mypy app
pytest                     # ~210 тестов, идёт около 70 секунд
uvicorn app.main:app --reload --port 8000
```

## Память и деплой (Render free, 512 МБ, жёсткий лимит)
Пики RSS, замерены в контейнере:
* MediaPipe — 237 МБ (основной провайдер, дефолт)
* InsightFace с обрезкой до трёх моделей — 274 МБ
* полный `buffalo_l` — 920 МБ, OOM-kill
* MediaPipe + WeasyPrint (PDF) — 321 МБ

Профиль сборки по умолчанию — `mp` (MediaPipe + PDF). Render Blueprint не умеет
передавать build args, поэтому дефолт в Dockerfile и есть прод-конфигурация.

**Обязательные системные библиотеки в образе.** Их отсутствие не видно в pytest,
потому что тесты идут на хосте, а не в контейнере:
* `libegl1`, `libgles2` — без них MediaPipe падает с
  `libEGL.so.1: cannot open shared object file` и молча уходит в демо-сетку.
  Баллы при этом остаются правдоподобными, поэтому баг коварный.
* `libpango-1.0-0`, `libpangoft2-1.0-0`, `libcairo2`, `libgdk-pixbuf-2.0-0`,
  `libharfbuzz0b` — WeasyPrint (PDF-экспорт).
* `fonts-dejavu-core` — кириллица в PDF. Без шрифта текст выходит квадратами.

**Проверяйте прод-профиль сборкой образа, а не только тестами.** Так нашлись обе
поломки выше. Скрипт проверки: собрать образ, поднять контейнер, прогнать
регистрацию → загрузку фото → отчёт → PDF, затем прочитать `/health`.

## Прозрачность расчёта
Формулы (`METRIC_FORMULAS`) и названия переменных (`VARIABLE_LABELS`) лежат в
`app/ml/constants.py` рядом с `METRIC_SPECS`. Держите их там: если формула
разойдётся с кодом, отчёт начнёт врать, а тесты этого не поймают.

Инвариант, закреплённый тестом: сумма вкладов категорий, делённая на сумму весов,
равна `overall_score` (погрешность 0.01). Вклад считается ПОСЛЕ добавления
гармонии — иначе сумма не сходится.

Переменные и вклады пишутся в JSON `summary` отчёта. Миграции БД не нужны,
старые отчёты открываются с пустым блоком «Как посчитан итог».

## Health-check
`/health` возвращает 200 всегда, но поле `status` = `degraded`, если БД
недоступна или ни один детектор не загрузился при выключенном демо. Код 200
выбран намеренно: Render перезапускает контейнер на неуспешный health, а
перезапуск проблему с библиотекой не чинит — получился бы цикл.

## Почта
Отправка через `app/core/mail.py` (`aiosmtplib`, extra `mail`, включён в оба
профиля образа). Без `SMTP_HOST` письмо не уходит, ссылка сброса пароля пишется
в лог. Ошибки SMTP не пробрасываются: сбой почты не должен ломать сброс пароля.
Тест поднимает настоящий SMTP-сервер (`aiosmtpd`, dev-зависимость) на localhost —
мокать отправку не нужно.

## Прочее
* Пол для метрик диморфизма берётся из профиля или с кнопок на странице оценки:
  MediaPipe его не отдаёт, `genderage` есть только у InsightFace.
* Пуш после каждого завершённого пункта прямо в `main`.
* Сложные места объясняем заказчику по-русски.

## Landmarks и метрики (грабли)
* Карта точек InsightFace 106 — источник ошибок. Уголки рта это 52/61 (НЕ 60/105,
  это точки губ). Правая внутренняя бровь — 102, не 97 (97 выше по y и зеркальна
  46). Индекс 30 — точка челюсти, не нос; кончик носа — 86.
* Пары зеркал для симметрии: истинная инволюция отражения, а не «похожие»
  индексы. Получена задачей о назначениях по зеркальным расстояниям, с
  проверкой взаимности. Любая ручная пара вроде 36↔90 вместо 36↔91 даёт ложную
  асимметрию.
* Координаты только изотропные. Точки, нормализованные раздельно по ширине и
  высоте, искажают все расстояния и углы аспектом кадра. Размер кадра живёт в
  `FaceLandmarks.image_size`; новые провайдеры обязаны его заполнять.
* Трихион (верх лица) берётся из bbox детектора. У схемы 106 нет точки лба.
  Без bbox лоб достраивается над контуром на `FOREHEAD_RATIO` (0.352, замерено
  на t1/grace/astronaut). Иначе верхняя треть нулевая.
* Ориентация: если после выпрямления по глазам подбородок выше трихиона, лицо
  перевёрнуто — добавляется 180°. На нормальных анфасах ветка не срабатывает.
* Ось симметрии считается по глазам и контуру, без кончика носа: смещённый нос
  не должен «создавать» асимметрию.
* `PLAUSIBLE_RANGES` намеренно широкие. Они ловят ошибки единиц измерения
  (пиксели вместо пропорций), а не «некрасивую» геометрию: узкие рамки молча
  выбрасывали метрики из отчёта на шумных landmarks.
* Демо-сетка (`demo_landmarks._TEMPLATE`) обязана быть строго симметричной
  относительно x=0.5: тест `test_demo_grid_is_mirror_symmetric` требует, чтобы у
  каждой точки было точное зеркало. Собирается из реального лица с симметризацией
  по парам и откалиброванным вертикальным ремапом (трети).

## Async SQLAlchemy
Связи в async-сессии не грузятся лениво. Любой код, который читает
`report.metrics` или `report.photo` после запроса, обязан запрашивать их через
`selectinload`, иначе `MissingGreenlet`. Это касается и сервисов (`ai.py`,
`reports.py`), и эндпоинтов (`exercises.py`).
